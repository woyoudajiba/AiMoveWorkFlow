# Spec: 剧集完整覆盖与对白保留

## 目标

让带有明确剧集边界的小说/剧本按“生成片段”拆分，而不是把一整集压缩成一个 15 秒片段。原文中的对白必须进入镜头计划，并在分镜审核卡片中可见；新建项目可以选择叙事视角。

## 功能要求

- Markdown 剧集标题是分析边界；每个剧集单独进入分析请求，跨集不得合并。
- 叙事视角支持自动分析、旁白视角和主角视角。旁白视角可生成旁白，但不得删除原文角色对白；主角视角改变观察和镜头组织，但对白仍归属于说话角色。
- 不读取剧本“制作备注/节拍”作为硬时长。存在剧集边界时，每集总规划控制在约 80–120 秒，目标约 100 秒；突破、Boss 战和关键打斗等重要剧情可按内容超出范围。
- 新建项目统一使用不超过 15 秒的自动片段。模型按对白、动作和节奏为每镜独立分配时长，镜头编号不代表秒数；每个片段仍是一个独立故事板和一个视频任务。
- 原文存在对白时，模型请求必须携带对白证据；返回结果不能所有镜头都为空对白，否则分析失败并进入一次纠正请求。
- 分镜卡片展示台词/旁白；无对白镜头明确显示“无台词”，避免审核者把隐藏字段误认为模型遗漏。
- 没有剧集边界的普通文章仍采用原有自然分段，不凭空扩写总时长。

## 非目标

- 旧项目的 30 秒记录仅作兼容读取，不进入新项目的分析和生成流程。
- 不把一个片段拆成多个视频任务；项目导出仍按片段顺序合并。
- 不自动覆盖已有分析结果；修改后需新建项目或重新导入原稿。

## 验证

- provider 单测验证按剧集拆块、时长预算、对白证据和不足时长拒绝。
- 域测试验证超过 100 个片段的完整剧集项目可以保存。
- `npm.cmd test`、`npm.cmd run check`、`npm.cmd run build`。
- 浏览器检查分镜卡片能看到对白字段，控制台无新增错误。
