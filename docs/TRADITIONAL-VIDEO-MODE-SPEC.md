# Spec: 传统多参考图视频模式

## 目标

在保留现有片段级故事板流程的同时，增加一个“传统模式”视频出口。传统模式按一个片段创建一个视频任务，直接使用当前片段实际涉及的场景参考图、出场人物的身份/场景造型参考图和关键物品参考图，不要求先生成九宫格分镜板。

## 非目标

- 不改变现有“九宫格模式”的整板生成、裁切、人工审核和片段视频流程。
- 不把传统模式拆成逐镜头视频任务；一个片段仍然只生成一条完整视频，项目导出仍按片段编号合并。
- 不自动静默丢弃场景、人物或关键物品参考图；超过供应商上限时使用确定的顺序合成参考图，并在任务提示词中说明。

## 用户场景

创建项目时选择“九宫格模式”或“传统模式”。分析完成后，用户在人物、场景和关键物品页面生成并审核素材。传统模式直接进入片段视频页面；点击生成时，系统按片段收集场景图、人物图和物品图，结合镜头计划提交一次视频任务。九宫格模式保持原有“生成整段分镜板 -> 审核 -> 生成完整片段视频”。

## 功能要求

- 新字段 `Project.videoMode`：`storyboard`（默认，兼容旧项目）或 `traditional`。
- 新项目创建页必须提供模式选择；服务端默认 `storyboard`，旧项目不迁移行为。
- `Scene` 增加参考图、参考图版本、审核状态和版本字段。场景支持生成、上传、审核；修改场景文字会使场景图及引用片段失效。
- 传统模式的片段视频前置条件：片段镜头计划有效；每个镜头引用的场景必须有当前审核场景图；出场人物必须有当前审核身份图和本场景当前审核造型（无人物时允许为空）；引用关键物品必须有当前审核参考图。传统模式不要求 `storyboardImage`、`storyboardApproved` 或 `shot.image`。
- 传统模式一次创建一个 `segment-video` 任务，任务提示词按镜头编号描述顺序、动作、对白、运镜和时长，并明确每张参考图用途；普通片段输出 3–15 秒。用户可以在片段页明确把同一连续场景扩展到 30 秒，扩展后必须重新生成/审核素材，并且只有支持固定 30 秒的模型（当前为熊猫 Seedance 2.5 特价按次）可以提交。
- 提供商图片上限由服务端统一处理：保留场景图、按镜头首次出现顺序保留人物图和物品图；超过当前模型上限时在付费请求前返回明确的 `REFERENCE_LIMIT`，要求拆分片段或减少同段引用，不能静默合成、截断或丢弃核心参考图。
- 历史记录、播放、下载、项目导出和客户端同步沿用 `segment-video` 记录，不新增逐镜视频记录。

## 验证计划

- 域测试：旧项目默认九宫格；传统项目允许无故事板但要求素材门禁；场景修改使引用任务失效。
- 服务测试：传统模式只创建一个片段视频任务，九宫格行为不变；缺少场景/人物/物品审核时返回明确错误。
- 提供商测试：传统请求包含场景、角色、物品多图及用途说明，不包含九宫格审核板；超限时请求数量与顺序可断言。
- 前端/浏览器检查：创建页模式选择、传统模式素材入口和视频页面文案在桌面布局可用。
- 运行 `npm.cmd test`、`npm.cmd run check`、`npm.cmd run build`，再打包 Windows 客户端并部署云端。

## 风险和开放问题

- 外部模型对多图用途遵循程度仍需真实供应商验收；本地测试只验证请求契约。
- 场景参考图生成会产生图片模型费用，沿用现有图片模型配置和任务恢复机制。
