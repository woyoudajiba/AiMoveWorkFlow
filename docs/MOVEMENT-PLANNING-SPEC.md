# 运镜规划规格

## 目标

让分析阶段先从受控的 120 条运镜语言库中为每个分镜选择运镜方案，并记录单镜执行和镜头衔接；生图阶段把方案写入故事板说明，生视频阶段按编号顺序执行。

## 数据契约

- `movementId`：`move-1` 到 `move-120`，引用 `docs/movement-language-library.txt` 中的条目。
- `movementPlan`：本镜的方向、速度、起止景别、焦点或特殊执行约束。
- `transitionPlan`：本镜与前后镜头的动作轴、视线、方向和转场衔接。
- 旧项目缺少这些字段时，服务端根据现有 `camera` 和 `action` 补齐兼容计划。

## 规则

- 运镜库是模型的参考资料，不会赋予文本执行工具或外部调用权限。
- 一个分镜只选择一个主要运镜；复杂复合运镜必须引用库中已有条目。
- 首镜优先建立空间，后续镜头承接动作方向、视线和道具状态。
- 视频提示词必须同时包含运镜库名称、执行计划和镜头衔接；不能只复述“中景/推进”。

## 验证

- 库解析出 120 条且编号连续。
- 分析输出包含合法 `movementId`，缺失字段可以兼容补齐。
- 故事板和视频提交提示词包含运镜库方案及镜头衔接。
- 旧分析结果、旧项目和 Agent 输入保持可读取。
