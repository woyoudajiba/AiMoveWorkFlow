# 批量制作操作规格

## 目标

让人物身份、场景造型、分镜图片和分镜视频可以按用户选择一次提交或审核，减少逐项操作；在长编辑表单中保持生成、上传和审核操作始终可见。

## 非目标

- 不改变人物身份、场景三视图、分镜审核和视频导出的既有门禁。
- 不自动重发状态未知的供应商任务，不覆盖当前版本之外的素材。
- 不引入第二套任务存储或绕过现有账号隔离。

## 契约

`POST /api/projects/:projectId/batch` 接收：

```json
{
  "kind": "character | look | shot",
  "action": "generate | approve | video",
  "targetIds": ["..."],
  "expectedVersions": {"target-id": 1}
}
```

服务端逐项复用单项操作的版本、素材、审核和任务状态校验，返回 `{ project, accepted, skipped, createdJobIds }`。`skipped` 包含目标 ID、稳定错误码和可展示原因；正在执行或待核实的任务不会重复提交。

## 交互

- 角色页和场景造型页提供“全选待处理 / 清空选择”、选择数量、批量生成和批量审核。
- 分镜审核页和视频页提供镜头选择、批量生成、批量审核或批量生成视频；原有整段操作继续可用。
- 角色、造型和镜头编辑器的关键操作区使用底部 sticky 布局，内容区预留空间，窄屏可换行。

## 验证

- 服务测试覆盖批量生成、批量审核、版本冲突、任务去重和门禁跳过。
- HTTP 测试覆盖批量路由和未认证写入边界。
- TypeScript、构建和真实浏览器桌面/窄屏检查固定操作区与选择工具条。
