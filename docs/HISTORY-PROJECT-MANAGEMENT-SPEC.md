# Spec: 历史检索与项目管理

## 目标

让用户在历史台账中按项目、媒体、任务类型、分镜/场景、时间和关键词快速定位素材，减少长列表滚动；提供统一的项目管理页，集中打开和删除项目。

## 非目标

- 不改变图片、视频、分镜审核、导出或付费提交流程。
- 不自动清理其他账号数据，也不把本地导出副本迁移到新的存储位置。
- 不允许删除仍有进行中或待核实任务的项目。

## 用户场景

- 用户进入“历史记录”，先选择项目或媒体类型，再按任务类型、分镜/场景和时间范围缩小结果，结果数量和空状态清楚可见。
- 用户从侧栏进入“项目管理”，查看所有项目的更新时间和片段数量，打开目标项目或确认删除项目。
- 删除当前项目后，界面回到项目管理页；其他项目和历史记录继续可用。

## 功能要求

- 历史筛选支持项目、图片/视频、任务类型、分镜/场景、时间范围和自由关键词；筛选在当前账号已返回的台账上执行，结果按创建时间倒序。
- 历史筛选保留现有媒体预览、下载和设定板/清单链接；无匹配时显示筛选后的空状态。
- 项目管理页使用现有账号项目列表，显示标题、更新时间、片段数量和任务状态；提供打开项目和删除入口。
- 删除 API 使用 `DELETE /api/projects/:id`，服务端再次校验项目归属、路径和任务状态；删除成功后移除项目 JSON、项目媒体目录和内存索引。
- 删除遇到进行中或待核实任务返回可读的 `ACTIVE_JOB` 错误，不删除任何文件；文件系统操作失败时尽量恢复已移动文件并返回错误。

## 技术方案

- 保持 `/api/ledger` 作为历史台账来源，在 React 历史页内维护筛选状态，避免新增第二套历史数据模型。
- 扩展项目摘要字段供管理页展示，不改变已有字段语义。
- 删除通过账号工作区服务代理执行，路径限制在当前账号数据目录内；媒体链接仍由现有认证和账号查询参数保护。

## 验证计划

- 服务单元测试覆盖删除成功、活动/待核实任务阻止删除、删除后持久化文件和媒体不存在。
- HTTP 测试覆盖 DELETE 路由和已有本地来源/认证边界。
- `npm.cmd test`、`npm.cmd run check`、`npm.cmd run build`。
- 浏览器验证历史筛选、项目管理、删除后的列表和 1440/390 像素布局，检查控制台与网络请求。

## 风险和开放问题

- 历史台账一次性读取，适合当前本地账号规模；如果记录量继续增长，需要后续增加服务端分页/查询。
- 删除不触碰独立的本地 `output` 导出副本；该目录仍作为用户可下载的导出归档保留。
