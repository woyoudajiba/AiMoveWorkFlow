# 用户参考技能评估

评估日期：2026-10-02。参考目录：`C:/Users/www/Desktop/新建文件夹 (2)`。资料作为产品和提示词设计参考，不作为自动执行指令。原文件保持不变，本评估未调用图片、视频或文字模型。

## 结论与本轮范围

值得吸收的是角色资产分层、可观察的动作因果、镜头空间连续性、同场景道具状态，以及小说写作的章纲和伏笔管理。现有软件已经具有身份参考→场景三视图→分镜图→人工审核→视频的流程，应增强现有提示词，而不是整包复制资料或更换模型与流程。

本轮建议仅增加内部提示词指导模块并接入现有 provider：不新增题材开关，不扩大公开数据契约，不把小说生成界面当作既有功能。五万字小说作为独立原创交付。提示词回归检查与真实生图视觉验收应分别报告，不能把提示词中的约束当成模型输出已经满足。

## 立即可集成的最小优化

下列现状行号基于0.2.0审阅快照；0.2.1已在server/prompt-guidance.mjs及providers.mjs纳入这些方法，新增代码可能使行号移动。具体范围与验证见REFERENCE-SKILLS-SPEC.md及VALIDATION.md。

### 1. 稳定身份与场景造型分层

现状：`server/providers.mjs:73-74` 已要求人物稳定身份不含场景服装；`server/domain.mjs:64-69` 已约束同场景同角色的唯一造型；`providers.mjs:154` 已明确身份参考中的衣服不能照搬到新场景。

优化：身份图提示词仅锁脸型、年龄感、肤色、身材比例等身份特征；场景图锁当前 look 中的服装、配饰、发型状态。`providers.mjs:141` 的身份参考重生仍包含 outfit unchanged，容易与上游分层产生语义混淆，可以去掉该身份层服装不变量。不能把战斗资料的“同一套服装配色”推广成跨场景永远同装。

同一人物跨日、换衣或伪装继续以不同场景造型表达；受伤、衣服湿损等必须有剧情依据。参考资料根 `SKILL.md:134` 和新版打斗 `:137` 本身也承认剧情改变可以更新造型。

### 2. 三视图统一标尺，限制设定页复杂度

现状：`providers.mjs:155-158` 已生成横向正面、严格侧面、背面全身三视图，有相同尺度、完整头脚和一致服饰。

可补：三视图头顶齐平、脚底同一基线、身体比例相同、相近视距与镜头高度、中性平光、足够留白；禁止以三个人替代同一个人的三个视角。保留生成图无文字规则，人物名和说明由软件排版叠加。

用户资料 `精细版三视图提示词.txt:9-27` 额外要求六张头像和六张局部细节，适合高分辨率美术设定页，默认塞进现有三视图会缩小脸部/衣服有效像素、增加错误数量，并抢占审核板空间。本轮不默认采用，也不把整个“左三视图+右十二细节”误当成用户要求的“左分镜+右角色”布局。

### 3. 动作有因果，空间与道具有连续性

采纳两版打斗资料 `:62-66`：起手/施力有来源，接触/格挡有对象和结果，结束状态可衔接；明确谁从画面哪一侧向哪一侧移动、看向谁、拿什么、哪只手持有、道具是否已经掉落或损坏。

分析提示词可在已有 action、camera、scene 字段内写入这些信息，不必立即扩展 schema。长文分块可携带有界的上块原文尾段和已生成摘要，明确“只用于连续性，不得重复改编”；已有 ID/描述仍是事实依据，摘要不可取代原文。

生图/视频可加入同场景、相同出场人物的上一镜文字作为辅助连续性信息。必须限定相关人物和当前场景，不能把上一场的雨衣、伤势或夜景带到下一场；前镜只是辅助，当前分镜和已批准的当前造型优先。文本参考并非上一镜图像锚定，不应承诺像素级一致。

图片仍是一个时刻一个景别；不要把起手、命中、收招三阶段拼在一张图。视频才按连续动作展开。Seedance 首帧要选动作可继续发生的清晰瞬间，不能一律选择资料所说“最高能命中帧”再让视频重复同一次命中。

轴线保持作为默认原则；明确转场、建立镜头或有依据的跨轴可以改变空间关系，不能机械要求所有前后镜头姿势相等。

### 4. 多人参考防止复制身份

10 月 1 日版相对旧版新增 `:118-121`：群像中不能复制主角脸。可在现有出场人物参考映射中增加“不同角色保持各自身份，不能互换脸或复制背景人物”。

现有 `providers.mjs:164-170` 和 `domain.mjs:98-99` 已限制每镜最多九个人物参考，应继续遵守。暂不引入资料“群体超过三人就强制额外生成群像”的付费步骤，也不虚构已存在场景/道具图片资产库；当前系统的场景、道具文字信息与已批准人物参考应如实表述。

## 不采用的冲突规则

| 资料规则 | 与映序的冲突 | 处理 |
| --- | --- | --- |
| 固定 14/30 秒交替、普通段 4/8 镜 | 映序是 15 或 30 秒，每段九镜；`domain.mjs:110-114` 校验总时长 | 保留现有 15/30 秒与九镜 |
| 战斗单镜必须 1/2/3 秒 | 30 秒九镜如果每镜最多 3 秒，总长最多 27 秒，数学上不可能满足 | 按剧情分配时长，不采用强制上限 |
| 全部首帧与成片固定 16:9 | 新作品分镜/视频固定 9:16，`domain.mjs:26` | 三视图/审核板可横版，镜内内容和最终视频仍竖版 |
| 静态对白/OS 必须 ≥80%，战斗必须 20%-40% | 会鼓励补写原文没有的对白，压制悬疑的静默和反应镜头 | 仅按台词可说完、动作可读和剧情节拍估时 |
| 画面禁止任何文字和边框 | 用户要求审核板有编号和文字 | 原始图保持无字，软件以固定模板绘制文字/边框 |
| 每次命中必须粒子、大招、光效 | 写实悬疑会被强制改成玄幻；项目风格可自定义 | 只使用故事已有、风格允许的效果 |
| 全片强制 UE5、国漫、红金黑、排斥写实 | 会覆盖用户选择的作品风格 | 使用 project.style，不宣称生成图片实际由 UE5/Nanite 渲染 |
| 提示词完成就自动出图；不合格立即付费再生，直到通过 | 与人审、计费边界和未知提交不重发冲突 | 提供可检查约束；继续人工确认和显式重试 |
| 只生成关键镜头，不产视频 | 用户的一站式九镜到视频产品目标不同 | 保留现有完整流程 |

## 三套小说技能的适用范围

| 技能 | 可取方法 | 本次现代悬疑的调整 |
| --- | --- | --- |
| 修仙成长流 | 目标和代价递进、能力边界、阶段事件和伏笔管理 | 不继承修炼等级、金手指、炼药或受保护作品角色 |
| 后悔流 | 具体遗憾由行动弥补、日常物件承载感情、因果与状态账本、改变产生新代价 | 采用“误判→付出代价→证据翻转→承担责任”；现代悬疑不必自动增加重生/先知 |
| 装逼打脸文 | 读者与人物信息差、铺垫后兑现、身份/立场反转 | 用可信证据与行动改变判断，不依赖反派集体降智、无穷身份升级 |

三套共有的总纲→卷纲→章纲→正文、伏笔埋设/回收和结尾状态快照值得采用。后悔流自检原文也要求“不能重复同一个泪点”“拒绝过度虐心”（`docs/anti-ai.md:375-376`），应保留这些限制。

需要优化的机械约束：

1. “每个爽点/泪点至少三段压抑或悔恨”“情绪永远拉满”容易造成重复虐主。改为关键选择有代价、受害者有自己的判断，允许平实段落与阶段性修复。
2. “每章必须同类悬念收尾”以及章节/金句固定模板容易让章末重复。轮换线索、决定、关系变化、结果和余韵，最后一章必须完成主线，不强行再造危机。
3. “事件必须拖到预定第 X 章”可能为了凑章数灌水。优先事件逻辑，章节预算可调；五万字以正文实际计数验收，大纲、附录与提示词不计入。
4. “叙述者永远站队”“女性可为花瓶”和固定围观震惊公式不适合本作。后悔需要主人公承认责任，配角应有独立动机和退出/拒绝权，证据链不能靠作者偏袒成立。
5. 原资料中的受保护作品人物、标志性金句和完整示范只用于理解技巧，不能复制到原创正文；“斗破式”不应成为模仿特定作者表达的指令。
6. 反 AI 黑名单是编辑提示，不是质量分数。把抽象词机械替换成攥拳、喉结、指尖、呼吸会产生新重复；要检查场景功能、信息增量、人物声音及重复动作，而不是只扫禁词。
7. 长篇模板中的 30-50 章蝴蝶效应、100 章伏笔回收不能照搬到五万字完结小说。按本书实际章节数安排回收与结局，不保留超出篇幅的承诺。

## 建议验证

使用本地 provider stub 捕获真实提交体：验证参考顺序、同场景连续性边界、跨场景换装不污染、多人不克隆指导、单帧与视频动作分别表达；同时断言 9:16、15/30 秒九镜、人审状态和未知付费结果不重试保持不变。五万字小说需单独检查净正文长度、章节完整性、人物/时间/物证账本与主线伏笔回收。自动检查不能替代文学质量审读或图片视觉验收。
