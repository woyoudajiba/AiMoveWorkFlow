# Spec: 客户端项目本地归档

## 目标

客户端允许为每个云端项目选择一个本地项目根目录，例如 `借我灵根`。目录下固定创建 `Actor_image`、`Story_image`、`Movie` 和 `Analysis`，把原稿/分析快照、人物与造型参考图、分镜图片、视频及清单保存到本地，减少服务器媒体长期占用。

## 非目标

- 浏览器端不增加本地目录选择或服务器清理按钮，网页继续使用现有手动下载。
- 不在同步失败、网络中断或文件未完整写入时删除服务器媒体。
- 不删除服务器图片和分析数据；本次只提供视频清理，保留网页历史与继续编辑能力。

## 用户场景

1. 用户在客户端“项目管理”中为“借我灵根”选择一个已存在或新建的文件夹。
2. 客户端自动创建四个固定子目录并显示目录位置。
3. 用户点击同步，客户端下载当前项目的原稿/分析、角色、造型、分镜、视频和清单。
4. 所有本地文件写入成功后，用户确认“清理服务器视频”；客户端提交已下载的视频路径，服务端只删除这些视频并更新项目引用。

## 功能要求

- 本地目录配置按 TDL 账号和项目 ID 隔离，路径只保存在客户端用户数据目录，不上传服务器。
- 下载文件只能写入四个固定目录；文件名由客户端根据项目编号生成，拒绝绝对路径、父目录、符号链接和未知扩展名。
- 每次文件先写入同目录临时文件，再原子改名；重复同步覆盖同名文件，任何单项失败都整体阻止云端视频清理。
- `Analysis/project.json` 保存完整项目快照，`Analysis/原始内容.txt` 保存原始输入，`Analysis/同步清单.json` 保存最近一次同步的本地文件清单，`Analysis/同步清理状态.json` 保存服务器视频清理状态。
- 服务端清理接口要求显式 `confirm: true` 和视频媒体路径数组；服务端再次校验当前账号、项目归属、路径和 `.mp4` 扩展名，并在保存项目状态失败时恢复文件。
- 清理后项目中的视频引用变为空并标记 `remoteDeleted`，图片、台账元数据和本地副本不受影响。

## 技术方案

- Electron preload 暴露 `chooseProjectFolder`、`getProjectFolder`、`syncProjectAssets` 和 `markProjectCleaned`，主进程使用原生目录对话框和带当前会话头的 HTTPS 下载。
- React 只负责生成受控资产清单和显示状态；浏览器运行时不调用这些桥接方法。
- 服务端新增 `POST /api/projects/:id/cleanup-videos`，复用当前认证和账号工作区。

## 验证计划

- 单元测试覆盖资产清单、路径/扩展名校验、目录创建、原子写入、重复同步和下载失败不清理。
- 服务测试覆盖清理权限、活动任务阻止、视频路径边界、状态保存失败回滚和图片保留。
- `npm.cmd test`、`npm.cmd run check`、`npm.cmd run build`，并在 Electron 窗口验证选择目录、同步和清理确认流程。

## 风险和开放问题

- 视频清理后网页不能再播放已删除的云端视频，只显示“已保存到本地”；用户必须保留本地项目目录。
- 当前不自动清理服务器图片和分析数据，后续可在确认历史与网页依赖后增加独立清理操作。
