# Spec: TDL 账号统一工作区

## 目标

同一个 TDL 账号在网页端和 Windows Electron 客户端使用同一套云端作品、素材、任务、模型配置和历史台账。客户端默认连接 `https://wsfile.cn/workf/`，因此两端看到的项目和历史记录来自同一账号目录。

## 非目标

- 本次不把旧客户端本机目录静默覆盖到云端。
- 本次不改变作品数据模型、生成供应商或 Agent API。
- 本次不部署生产服务器；部署仍需单独执行并验证云端环境变量。

## 用户场景

- 用户在网页端登录后创建或生成作品，再打开客户端登录同一 TDL 账号，可以继续看到同一项目和历史素材。
- 网页端和客户端同时在线时，同一账号的两个本地会话都能访问该账号工作区；退出其中一端不会误踢掉另一端。
- 客户端安装到用户选择的目录后，启动仍使用云端工作区；旧本地数据保留在原用户数据目录，等待后续显式迁移工具。

## 功能要求

1. Electron 正式包默认加载云端工作台地址；开发和隔离 smoke 测试继续使用本地服务。
2. 云端 HTTP 服务允许配置的公开 Host/Origin，并继续要求 `X-Local-Client` 来源标记与同源校验。
3. 同一进程允许同一 TDL 账号建立多个本地会话；会话按各自 ID 校验，退出只清理当前会话，最后一个会话退出时才撤销 TDL 会话。
4. 作品、媒体、配置、任务和历史均由现有账号哈希目录提供，网页和客户端不创建第二套账号目录。
5. 网页默认下载 NSIS 安装包，安装器关闭一键安装并允许用户选择安装目录。

## 验证计划

- 本地会话单元测试：同账号并发会话、单端退出、不同账号隔离。
- HTTP 契约测试：允许公开 Host/Origin 时仍保留来源校验。
- `npm.cmd test`、`npm.cmd run check`、`npm.cmd run build`。
- `npm.cmd run dist:win` 后检查 NSIS `.exe` 产物和安装器配置；Electron smoke 使用本地隔离模式。

## 风险和开放问题

- 已存在于旧客户端本机的数据不会自动上传，避免无确认的覆盖和重复生成；后续如需迁移，应设计显式预览、冲突处理和媒体上传契约。
- 云端生产服务必须设置 `AI_FRAME_ALLOWED_HOSTS=wsfile.cn` 与 `AI_FRAME_ALLOWED_ORIGINS=https://wsfile.cn`，并重新部署后客户端云端入口才可用。
