# 片段级整板生图规格

## 目标

让新作品按“小说片段 -> 一次整板生图 -> 人工检查 -> 逐镜视频 -> 数字编号导出”工作。这里的“九宫格”是片段分镜板的统称，不固定为九格：分析模型根据叙事节奏决定 3..12 个镜头，模板只决定分镜板的排版和镜头槽位。

整板生图一次携带本片段的镜头计划、场景状态和出场角色文字事实；对本片段实际出场的角色，优先上传已审核且为当前版本的场景三视图，缺少场景三视图时回退到当前身份参考图。参考图只用于锁定对应人物身份和造型，不生成角色参考区，也不得复制三视图排版。没有当前参考图的无人物或纯文字内容继续走纯文字路线。

## 非目标

- 已存在的作品不自动迁移到片段级模式，仍按原有逐镜和场景造型审核门禁运行。
- 不把模型返回的整板图片直接当作最终竖屏视频首帧；服务端为每个镜头保存由整板生成结果裁出的竖屏画面。
- 不绕过人工检查；整板生成完成后，用户仍需确认整板和镜头画面，再生成视频。
- 不把片段时长解释为绕过供应商限制。MiniMax 与火山方舟都按各自模型允许的最小/最大时长提交，超出范围时在本地拒绝。

## 数据和兼容

- `Project.generationMode`：`legacy-shot` 或 `segment-board`。旧数据缺省为 `legacy-shot`；新建作品默认 `segment-board`。
- `Segment.shotCount` 等于分析模型实际返回的镜头数，片段级模式允许 3..12；旧模式仍要求 9。
- `Segment.storyboardImage`、`storyboardImageVersion`、`storyboardApproved` 保存整板图片及人工审核状态。
- `Job.kind` 增加 `storyboard`，目标为 segment ID。一个片段只允许一个当前版本的整板任务。
- 整板任务完成后，服务端保存 `storyboardImage`，并从整板中按模板槽位生成每个镜头的竖屏 `Shot.image`。镜头图片标记为当前版本但保持未审核，防止模型成功被误当作人工通过。

## 生图提示词

提示词必须明确：

- 这是一个片段级完整分镜板，一次生成全部镜头，不是把独立图片拼接到空白模板。
- 镜头数、顺序、动作、景别、台词短标签和每镜时长来自分析结果；每个镜头只表现一个时刻。
- 角色文字事实只作为镜头规划和画面描述的辅助；服装、发型和配饰服从当前镜头所属场景，换场景不得复制上一场衣着。
- 整板只生成编号镜头、镜头画面和短文字标签，不添加角色妆造、正侧背三视图或其他人物参考素材；上传的参考图只作为模型输入，不得出现在整板画面中。
- 画面主体按竖屏镜头构图，整板本身可横向排版；禁止生成水印、品牌和未声明角色。

## 视频提示词和输入

- 每个视频使用对应镜头的竖屏裁切图作为图片 1。
- 每个视频使用对应镜头的竖屏裁切图作为图片 1。MiniMax H3 V2 在有角色参考图时把图片 1 和角色图全部作为 `reference_image`，在没有角色参考图时才把图片 1 作为 `first_frame`；不能混用首帧模式和参考图模式。火山方舟继续使用 `first_frame` 加后续 `reference_image`。
- 视频提示词要求模型以镜头图片为视觉事实，参考图只约束人物身份、妆造和服装状态；保持竖屏 9:16、左右位置、道具和动作连续，不新增镜头或分屏。
- MiniMax 与火山方舟在片段级模式使用已分析的片段时长和镜头计划，并遵循各自最小/最大值。

## 验证

- 域测试：片段模式允许可变镜头数，旧模式仍拒绝非 9 镜；新建项目默认片段模式。
- 提示词测试：整板请求是一次请求且包含镜头数、场景妆造和“不是手工拼图”约束；视频请求包含参考图角色和一致性说明。
- 服务测试：整板任务只生成一个任务，完成后为所有镜头写入裁切图且保持未审核；过期版本和活动任务不重复提交。
- 浏览器测试：故事设置显示 AI 决定镜头数/时长；分镜页提供整段生成与整板审核，桌面和 390px 宽度无溢出。

## 风险

- 外部生图模型未必严格按模板槽位绘制，裁切结果需要人工检查；失败时保留整板任务回执，不自动重复付费。
- 两家视频供应商都把镜头裁切图作为主要视觉依据；MiniMax 的参考模式和方舟的首帧加参考图模式分别遵循各自输入契约。真实生成仍需人工检查一致性。
