# 分镜审核易用性修复

## 目标与范围

让模板选择、任务状态和未提交编辑反映当前作品的实际情况，减少刷新丢失文字和错误提示误导。沿用现有工作流，不改变人工审核、供应商提交、素材版本或视频导出语义。

## 行为要求

1. 制作流程统一称为“分镜审核”；保留每段 9 个镜头的业务约束。模板卡片依据连续场景、镜头容量和角色容量展示预计页数、造型续页与空位，不以 `ceil(9 / 容量)` 代替场景分页。
2. 当前镜头失败提示只使用当前输入版本的最新任务。历史任务仍可在任务记录中查阅；旧失败不得覆盖新版本或后续成功。
3. 审核板单页图片加载失败时提供“重新加载本页”，只重新请求既有图片，不生成新导出或付费任务。
4. 新建项目及故事、人物、场景、造型、镜头的未保存文字编辑保存在当前浏览器。数据按项目和对象隔离，7 天过期，仅允许白名单编辑字段，不保存密钥、媒体或模型配置。恢复时明确提示仍须手动保存；成功保存清除相应草稿；存储不可用或损坏不得阻止编辑。

## 验证

- 为版本隔离、分页边界和草稿保存/恢复/清理/损坏补充行为测试。
- 运行现有测试、check、TypeScript/Vite build。
- 真实浏览器验证桌面与 390px 窄屏；测试模板切换、图片失败重载、刷新恢复及保存后草稿清理。浏览器验证使用本地隔离数据或拦截外部提交，不调用付费模型。

## 风险

浏览器存储属于本机临时恢复，不替代项目备份；配额不足和浏览器清理可能使恢复不可用。分页说明必须与导出算法保持一致；新增回归用例应与导出页数对照。供应商恢复和自动视觉质检不属于本次修复。
