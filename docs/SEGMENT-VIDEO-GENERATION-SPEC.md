# Spec: 片段级完整视频生成

## 目标

在 `segment-board` 模式下，一个故事板片段只创建一个视频任务。视频模型接收按顺序裁切、去除审核文字区的 N 张单镜头画面和片段镜头计划，按 1 到 N 的编号顺序生成一条完整视频。带编号和说明文字的整段审核板只用于人工检查，不上传给视频模型。项目导出继续按片段编号合并完整片段视频。

## 非目标

- 不改变 `legacy-shot` 模式的逐镜头视频兼容行为。
- 不在本次改动中自动提交真实付费视频请求；提供商请求结构用 mock 测试验证。
- 不把一个片段拆成多个视频文件，也不在历史台账中伪造多个镜头视频记录。

## 用户场景

用户审核一个片段的整板分镜和裁切画面后，在“视频与导出”页面点击生成。系统显示一个“片段完整视频”任务，提示词要求模型按故事板编号顺序连续表现所有镜头。完成后用户可以在片段卡片、历史台账和项目导出中播放或下载该完整视频。

## 功能要求

- `segment-board` 的 `generate-videos` 只创建一个 `segment-video` job，目标为 `segment.id`。
- 片段视频保存到 `segment.video`、`segment.videoVersion` 和 `segment.videoDuration`，不写入 `shot.video`。
- 提交前必须满足整板审核、所有裁切画面当前且全部镜头已审核。
- 提示词必须包含片段时长、画幅、镜头 1 到 N 的动作/景别/台词，并明确连续发生、禁止跳过/倒序/拆成多个视频。
- 每个镜头的竖屏裁切图是对应镜头的主要视觉事实；裁切时移除底部审核文字区。带编号、标签、格线和说明文字的故事板整图只用于人工检查，不作为视频输入。镜头裁切图和角色参考图超出供应商图片上限时，服务端在本地合成一张无标签的顺序参考图，并按模型上限发送，不增加图片模型调用。角色参考图只能用于身份和造型一致性，并在视频提交时作为后续参考素材上传。每个提供商最多按其协议发送受支持的参考图。
- 视频提示词的最后一句固定为“与参考素材完全一致”，必须位于实际发送给供应商的文本末尾。
- 项目级导出在 `segment-board` 模式使用各片段完整视频；旧模式继续使用镜头视频。
- 历史记录记录一条 `segment-video`，播放和下载链接指向完整片段视频。
- 旧项目缺少片段视频字段时按空值迁移，不破坏已有镜头视频数据。

## 技术方案

- 新增 job kind `segment-video`，版本绑定片段模板、故事板版本、镜头版本、片段时长和画幅。
- 新增 `submitSegmentVideo(project, segment, businessId, requestedModel)`，保留 `submitVideo` 作为旧模式适配器。
- 新增 `runSegmentVideo`，沿用已有异步提交、持久化 provider task ID、轮询、MP4 解码校验和 H.264/AAC 转码流程。
- `requireExport` 和项目导出按生成模式选择片段视频或镜头视频。
- 前端在片段级模式显示一个片段视频入口，镜头卡片只展示故事板镜头计划，不显示单镜头生成按钮。

## 验证计划

- 服务测试：片段级只创建一个 `segment-video` job；旧模式仍创建镜头 jobs；完成后写入片段视频并记录一条台账。
- 提供商测试：请求提示词包含编号顺序、完整片段和禁止拆分语义，输入只包含按顺序的单镜头裁切图和角色一致性参考，不包含带字整板。
- `npm.cmd test`、`npm.cmd run check`、`npm.cmd run build`。
- 浏览器检查视频页文案、任务数量、播放器和历史记录；真实付费模型生成另行验收。

## 风险和开放问题

- 不同提供商对多图参考和 30 秒时长支持不同；提交函数必须按模型协议裁剪参考图并保留明确错误。
- 旧的单镜头任务仍可能存在，恢复查询时继续按旧 job kind 处理。
- 云端 Linux 必须使用 Linux ffmpeg/ffprobe，发布时不能复用 Windows 二进制依赖。
