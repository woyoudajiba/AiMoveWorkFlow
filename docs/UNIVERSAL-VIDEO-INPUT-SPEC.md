# 通用文本转视频规格

## 目标

让项目从“小说短剧”扩展为任意可读文本的短视频制作入口。用户创建项目时选择最终画幅，系统在分析、整板生图、镜头裁切、视频请求和成片导出中保持同一比例；输入可以是自动识别的小说、剧本、新闻、论文、讲解文章或其他文章。

## 非目标

- 不改变旧项目的文件结构和 `novel` 原文字段名称。
- 不为没有人物的内容强行创建角色、身份图或造型三视图。
- 不在新闻、论文和讲解文章中补写原文没有提供的人物、数字、机构、引用或结论。
- 不调用真实付费模型作为自动化验证的一部分。

## 数据契约

- `Project.sourceType`: `auto | novel | script | article | paper | news`，缺失的历史项目按 `auto` 读取。
- `Project.narrativeMode`: `auto | narrator | protagonist`，旁白视角适合广告、纪录片、新闻和论文讲解；主角视角优先组织主角观察、反应和主观镜头。原文明确对白在三种模式下都必须保留。
- `Project.aspectRatio`: `9:16 | 16:9`，新项目默认 `9:16`，用户可在创建时选择。
- `Shot.sourceEvidence`: 可选的原文依据，说明镜头与输入文本的对应事实或段落；没有可靠依据时为空，不得编造。
- `characters` 允许为空数组；镜头的 `characterIds` 允许为空数组。

## 行为要求

1. 片段整板模式仍由模型决定 3–12 个镜头和不超过 15 秒的分析时长，只调用一次图片模型；用户可在审核阶段把一个连续片段明确扩展到 30 秒，扩展后重新生成/审核并使用支持 30 秒的模型。
2. `16:9` 项目的整板裁切图输出 1280×720，`9:16` 项目输出 720×1280；审核设定板记录同样的镜头比例。
3. Seedance/其他视频请求使用项目画幅；提示词明确首帧是唯一视觉事实，并要求保持画面构图和比例。
4. 分析提示词按 `sourceType` 提供适配规则：小说保留叙事因果，剧本遵循场次和对白，新闻/论文/文章只把原文可验证事实转成可视化镜头。
5. 无人物内容使用地点、物体、图表、地图、界面、文件或过程画面完成镜头，不进入人物审核门禁。

## 验证

- 单元测试覆盖两种画幅的整板裁切尺寸、视频请求比例和最终导出尺寸。
- 单元测试覆盖无人物分析、各类 `sourceType` 提示词以及项目/Agent 创建参数。
- 运行 `npm.cmd test`、`npm.cmd run check` 和 `npm.cmd run build`；修改 UI 后补充真实浏览器创建项目和移动端检查。
