# 参考技能融合与长篇小说交付规格

日期：2026-10-02。目标版本：0.2.1。

## 用户目标

审阅桌面“新建文件夹 (2)”中的分镜、动作、三视图及三类小说资料，将有价值的方法优化后纳入映序，并依据后悔流资料创作一部现代悬疑＋后悔反转的完整五万字小说。

## 软件改进范围

1. 将服务端提示词方法集中为可测试的内部模块；桌面界面、JSON CLI 与 MCP 继续共用同一业务服务，无需 Agent 使用另一套提示词。
2. 改编保留原文事件、人物认知与揭示顺序；对白可视化、情绪由行动呈现，禁止把所有题材改成重生、打脸或强行和解。
3. 分块分析增加有界的前文尾段和已处理片段摘要，只用于接续，不重新改编旧段；原文优先于模型摘要。
4. 加强动作的起因、受力、反应和结果，以及轴线、左右位置、视线、道具持有、伤势和服装连续性。单张图保持单时刻；视频保持单镜连续动作。
5. 人物身份图只锁定稳定身份；旧 `legacy-shot` 的场景三视图统一同高、同地线、严格正侧背，服装和配饰以当前场景为准。新 `segment-board` 不要求先生成独立三视图，当前片段妆造在完整分镜板内一次表达并随镜头保持连续。
6. 仅在紧邻前镜属于同一场景且出场人物集合相同时传递有界的文字连续性参考；该参考不是已审核图像，不自动获得审核状态，不带入其他场景服装或新人物。

## 保持不变

9:16 单镜和视频；15/30 秒片段；横版文字审核板及三种模板；账号隔离与付费提交去重。不引入新的第三方请求、依赖、自动审核或自动付费重试。原始资料不修改。旧作品的 `legacy-shot` 数据继续保留九镜兼容；新片段的 `segment-board` 允许 AI 按剧情选择 3–12 镜。

新片段流程为“小说分析 → 一次生成完整片段分镜板（只生成画面和镜头文字）→ 检查整板与竖屏裁切 → 审核 → 提交一条完整片段视频”。分镜生图不上传角色形象图片；场景服装、配饰和发型依据镜头文字设定表达。生成视频时，按镜头顺序提交去除底部审核文字区的单镜头裁切图，第一张作为起始画面，后续裁切图和角色参考图作为一致性参考，整板不上传；视频提示词最后固定追加“与参考素材完全一致”，并要求按顺序连续发展，不重新生成分镜板、分屏、字幕或额外人物。

## 不直接采用

14/30 秒交替、全资产 16:9、固定 UE5 红金黑、对白必须占 80%、打斗每镜最多 3 秒、失败无限生成、缺失脚本/引用、小说固定性别模板和已知作品示例。小说写作技法只在原剧情存在相应情感时用于改编，不凭空补剧情。

## 小说交付

原创、现实悬疑、有限视角，后悔通过承担责任与具体行动兑现。24 章左右，目标约 55000 汉字；仅正文的汉字数必须不低于 50000，不把标题、大纲、自检或重复内容计入。输出完整 UTF-8 TXT 和 Markdown、创作设定与章纲、实际字数与一致性检查说明。按统一故事圣经分段撰写、检查交接和伏笔回收；不把创作质量声明为经过外部模型或读者验收。

## 验收

- 新增连续性测试覆盖第一块、跨块、同场景、跨场景、不同人物、长输入和注入式正文作为数据；验证真实 provider 请求携带规则。
- 原有测试、check、build 通过；更新桌面 portable 并实际启动 smoke。
- 完成原始资料评估记录；小说核对正文汉字数、章序、完整结局、重复段、时间线和核心证据链。
- 本轮不新增 UI、不部署云端、不提交 Git、不调用图片/视频收费服务。
