# 强制删除与客户端更新规格

## 目标

- 在项目管理中保留普通删除的活动任务保护，并提供一次明确的强制删除确认。
- 强制删除后，项目记录、服务器媒体和未开始任务立即失效；晚到的模型结果不能重新写回或留下项目媒体。
- Electron 客户端提供检查更新按钮。第一次点击检查固定清单，发现新版本后第二次点击下载、校验并启动安装包。

## 非目标

- 不取消任务供应商已经产生的外部计费或远程任务。
- 不允许网页端触发客户端安装，也不接受渲染进程提供任意下载地址。
- 不在本轮自动部署云端或发布安装包。

## 契约

- `DELETE /api/projects/:id` 默认保持现有行为；请求体 `{ "force": true }` 才进入强制删除。
- 强制删除响应仍为 `{ id, title }`；非法 `force` 类型返回输入错误。
- 更新清单固定为 `/workf/downloads/latest.json`，包含 `version`、受控 `url`、64 位 `sha256` 和可选 `releaseNotes`。

## 验证

- 服务测试覆盖普通删除、活动任务拒绝、强制删除和晚到任务不回写。
- HTTP 测试覆盖删除请求体转发。
- 更新模块测试覆盖版本比较、URL/清单校验、SHA-256 校验和安装启动。
- 运行全量测试、检查、构建和打包 Electron 烟测，并检查客户端更新桥接存在。

## 风险

- 已提交给供应商的任务仍可能产生费用；界面必须明确提示这一点。
- 更新安装包必须可访问且哈希匹配；失败时保留当前客户端并报告错误。
