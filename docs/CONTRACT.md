# Implementation contract

All backend modules are ESM .mjs. Frontend fetches JSON; errors are {error: string, code?: string}. Mutation requests set X-Local-Client: aiframe. URLs and paths in project assets are relative server URLs `/media/<projectId>/<generatedName>`; never arbitrary local paths.

Project: {id,title,novel,style,llmModel,visualStyle:'photorealistic'|'2d-animation'|'3d-animation',workflowVersion:2,aspectRatio:'9:16'|'16:9',duration:15|30,durationMode:'auto'|'fixed',generationMode:'segment-board'|'legacy-shot',createdAt,updatedAt,characters:Character[],scenes:Scene[],looks:Look[],segments:Segment[],jobs:Job[],exports:Export[],analysisWarnings?:{episodeNumber,totalDuration,maximumDuration,message}[],exportHistory?:Export[],legacyExports?:Export[]}. `llmModel` is a validated text-model preset selected for this project; it never contains a credential. Legacy projects are migrated to the default preset. `analysisWarnings` reports a completed analysis whose episode exceeds the suggested 80–120 second planning range; it never means source content was dropped.
Project.durationMode: 'auto'|'fixed' (legacy records default fixed). New UI projects default to auto with a 15-second project budget; analysis still creates each content-sized segment at no more than 15 seconds, while a user may explicitly promote one continuous segment to 30 seconds before video generation. Project.generationMode defaults to legacy-shot for old records; new UI projects use segment-board. In new segment-board projects, each analyzed segment contains 3–12 shots selected by the model and a validated duration total no greater than 15 seconds. An explicitly extended segment carries `extendedDuration:true`, retimes its shots and must be regenerated/reapproved before a 30-second-capable video model can be used. legacy-shot retains exactly nine shots for compatibility.
New projects require 9:16, including subsequent PATCH operations. Existing 16:9 projects retain their source/video aspect ratio. Landscape refers to the review board layout, not a new video aspect ratio.

Scene: {id,name,description}. A scene is one continuous time/place and costume state. A costume change can require another scene at the same location.

Its reference is one landscape front/side/back three-view image of the same character in that scene's costume. Segment: {id,number,title,summary,duration:number (3–15 for fresh analysis; 3–30 after explicit extension or legacy migration),extendedDuration?:boolean,generationMode:'segment-board'|'legacy-shot',shotCount:number,storyboardImage:string|null,storyboardImageVersion:string|null,storyboardApproved:boolean,storyboardLayout?:object,boardTemplateId:'classic-nine'|'eight-one'|'three-three',shots:Shot[]}. In segment-board, storyboardImage is the one complete landscape board returned by the image provider; storyboardLayout describes its crop map and each shot.image is a server-side crop. Shot: {id,number,duration:number,sceneId,scene,action,camera,movementId?,movementPlan?,transitionPlan?,dialogue,narration?,characterIds:string[],image:string|null,approved:boolean,version:number,trimStart:number,video:string|null,videoVersion:number|null}
Shot.imageVersion?: number. Successful generation/upload stamps the resulting current version; content edits leave the original image stamp unchanged. Timing-only edits preserve a previously current image stamp at the new version; already stale or unverified stamps are never upgraded.
Shot also records videoDuration:number|null. Timing edits inside this verified source length preserve the raw video with a new version and revoke approval; content changes invalidate it.
Job: {id,kind:'analyze'|'character'|'look'|'image'|'storyboard'|'video'|'export',targetId,status:'queued'|'running'|'completed'|'failed'|'unknown'|'interrupted',progress:number,analysisModel?:string,error?:string,providerTaskId?:string,businessId?:string,createdAt,updatedAt}. An analysis job snapshots the project's `llmModel`; retries and continuation use that snapshot.
Export: {id,segmentId,number,templateId,videoUrl,gridUrl,pages:BoardPage[],manifestUrl,csvUrl,createdAt,localOutput?:{status:'saved'|'failed',directory?:string,files?:string[],error?:string}}. BoardPage: {number,gridUrl,shotNumbers:number[],lookIds:string[],continuation:boolean,layout}. gridUrl aliases the first page; consumers must iterate pages for a complete delivery.

Character identity edits invalidate every look for that character and all dependent shots. Look edits/replacements invalidate only shots matching its sceneId and characterId. Scene name/description edits invalidate that scene's looks and shots. Generation, shot approval and video gates require current reviewed identity/look references; shot approval/video also require current image stamps. Late responses for old versions cannot replace current assets. Existing workflow-1 projects migrate to unapproved scene/look drafts while retaining original media/text; old shots become stale and old active non-analysis tasks are interrupted without another POST. Existing export records move to legacyExports and are not reused for the new scene workflow.

熊猫 `xiongmao-seedance-2-5-special` 使用供应商模型 `seedance-2-5-special`，固定 30 秒、支持 720p/1080p 和最多 30 张参考图。普通分析仍把新片段限制在 15 秒以内；只有显式扩展的连续片段才允许该固定时长模型。

The six text models and their fixed routes are defined by server/llm-models.mjs. llmKey only serves Coding Plan; tokenPlanKey only serves Token Plan; minimaxKey only serves MiniMax-H3 / MiniMax-H3-Max; the shared Xiongmao key serves `xiongmao-minimaxh3`, `xiongmao-seedance-2-0-official[-fast|-mini]`, `xiongmao-seedance-2-0-promo[-fast|-mini]`, `xiongmao-seedance-2-0-special[-fast|-mini]`, and `xiongmao-seedance-2-5-special`; arkKey only serves the allowlisted Volcano Ark Seedance models. Seedance `-fast` and `-mini` are internal model suffixes that map to the same remote model with a different top-level `quality` value; the Seedance 2.0 special variants use `高清` / `快速` / `标准`, are fixed at 15 seconds, and expose approximate live `pricePerCallCnyRange` values rather than per-second rates. `xiongmao-seedance-2-5-special` maps to `seedance-2-5-special`, is fixed at 30 seconds, supports 720p/1080p and up to 30 reference images, and has no configured price estimate until the supplier price is supplied. MiniMax H3 V2 treats frame roles and reference roles as mutually exclusive: with character references the approved still is the first `reference_image` and all character images use `reference_image`; without character references the approved still uses `first_frame`. Ark keeps its `first_frame` plus subsequent `reference_image` contract. The 熊猫Ai provider uploads local reference images in order to `POST https://panda.token6688.com/v1/files`, submits top-level `model`, `prompt`, `mode`, `images`, `duration`, `resolution`, `quality` (for Seedance), `aspect_ratio` and `client_request_id` to `POST https://panda.token6688.com/v1/videos/generations`, then polls `GET https://panda.token6688.com/v1/tasks/{task_id}` until a final state and consumes the returned `output_url`/documented equivalent result URL. llmConfigured reflects the currently selected model, while each catalog entry reports its provider's configured flag. These flags indicate presence, not provider authentication or quota verification. Empty credential values retain the saved value. Unknown model IDs, arbitrary endpoints and unknown config fields are rejected. An analysis captures the model and credentials once before chunking; selection changes affect subsequent analyses, and failure never falls back to another model or key. Public config and Agent output never return credentials.

Image model choices and generation parameters come from server/image-models.mjs. Default is gpt-image-2.5; catalog includes the five SF智投 choices and existing Nano Banana Fast/2 choices. Unsupported model IDs are rejected before submission. No credentials are included in catalog metadata. See IMAGE-MODELS.md for source evidence and parameter differences.

StoryboardPreview: {kind:'storyboard-preview',projectId,segmentId,number,duration,aspectRatio,templateId,gridUrl,pages:BoardPage[],manifestUrl,csvUrl,requiresReview,assetsCurrent,hasStaleAssets,hasUnverifiedAssets,hasMissingReferences,createdAt}. A single page is 001.jpg; multiple pages are 001-01.jpg, 001-02.jpg, etc. Segment-board accepts 3–12 source crops; legacy-shot continues to require nine. Source images must resolve within the same project. Current image generation/unknown replacement tasks block snapshot creation. Unapproved, stale and unverified stills are allowed, with original URLs, version stamps, shot text, scene/look mappings and approval states retained in the manifest. Statuses are current, stale, unverified (missing/invalid stamp), or missing. Any non-current asset, missing scene look or unapproved entity requires review without altering the original approval. CSV retains complete text even when the fixed layout explicitly truncates long text. Preview creation does not alter projects, approvals, tasks or video export records.

Board templates are defined by server/board-templates.mjs: classic-nine is 9 slots/2 looks in 3×3; eight-one is 8 slots/1 look in 4×2; three-three is 3 slots/3 looks in 3×1. Slots and text positions remain fixed, missing slots show placeholders, and source images use contain. Each page contains one continuous scene only. Shots beyond capacity continue in order; looks beyond capacity produce marked costume continuation pages repeating that shot group so every look is represented. In segment-board, the template controls review-board layout only; the generated board still contains the AI-selected number of panels and the server crops each panel to the project aspect ratio while removing the reserved review-label band. The final video uses the ordered annotation-free crops and character references; it never receives the board text, frames or the three-view panel.

PATCH segment accepts `boardTemplateId` and/or an explicit `duration` of 15 or 30 seconds. A 30-second change is allowed only for auto segment-board projects, proportionally retimes the shots, sets `extendedDuration:true`, clears current approvals/media versions and requires new storyboard review; switching back to 15 seconds reverses that flag. Unknown IDs, unsupported durations, active segment tasks and fixed-duration changes fail with 400/409 INVALID_INPUT or ACTIVE_JOB. A different template preserves shots and approvals when no duration changes are requested and is rejected with 409 ACTIVE_JOB while that segment has a queued/running export. Export job inputVersion is JSON.stringify({templateId: segment.boardTemplateId, shots: segment.shots.map(s => [s.id,s.version,s.videoVersion,s.trimStart,s.duration])}). Completed exports append historical snapshots; content edits continue invalidating affected current exports. Agent export_segment selects the latest export explicitly matching the current templateId; unmarked legacy or different-template exports are not reused as current fixed-template output.

Individual character/look/shot action bodies may include `expectedVersion:number`; mismatch is rejected inside the state lock with `409 VERSION_CONFLICT`. Generation can include `reuseExisting:true` to reuse a same-version existing asset (`referenceVersion`, `imageVersion` or `videoVersion`), while omitted/false preserves explicit regeneration and active/unknown task deduplication. Approval can include `reviewedVersion:number`; mismatch returns `409 STALE_INPUT`. Segment-board approval uses the serialized storyboard input version and also checks every current vertical crop. Existing UI clients may omit these fields. Agent clients must explicitly attest to the inspected version and must not treat generation completion as approval. JSON CLI and MCP share 26 strict tools, including approve_segment_board, six scene/look tools, list_board_templates and set_board_template; no credential, arbitrary-shell or external-URL upload tool is exposed. Module boundaries: providers/media/network own external transports and local assets; domain/service own validation, persistence, revision invalidation and queues; http/config own local requests and credential settings; Electron owns Windows credential encryption and lifecycle; src owns the interactive client.
## Explicit continuation after an uncertain analysis

`POST /api/projects/:id/jobs/:jobId/retry-analysis` requires `{ "confirmDuplicateCost": true }` and the ordinary authenticated write boundary. Only a current `analyze` job with status `unknown` can be continued. Missing confirmation returns `RETRY_CONFIRMATION_REQUIRED`; an old source returns `STALE_INPUT`; running or non-analysis jobs return `CANNOT_RESUME`. Existing results cannot be overwritten. Duplicate requests for the same original job return its already-created continuation without another submission.

The original job remains `unknown` with `analysisRetryAcceptedAt` and `analysisRetryJobId`; the continuation has `analysisRetryOf`. Only that explicitly linked continuation can reopen a pending checkpoint. Previous validated chunks are reused when source/settings/model match. An additional timeout requires a separate acknowledgment for the latest uncertain job. Restart and ordinary `analyze` do not grant consent or automatically replay uncertain requests. Image/video behavior is unchanged.

Qwen preset analysis uses `enable_thinking:false` for both initial JSON and one corrective response. Other model families do not receive this Qwen parameter. The default analysis request timeout is 600 seconds; `AIFRAME_ANALYSIS_TIMEOUT_MS` accepts 1000..600000. These transport changes preserve existing validated checkpoint data.

剧集总时长的 80–120 秒是建议规划范围，不是内容截断门槛；突破、Boss 战和关键打斗等重要剧情可以超出范围。新分析的单段视频最多 15 秒；用户可在审核页把一个连续场景显式扩展到 30 秒，再选择支持 30 秒的模型。分析会保留全部已验证片段并在项目返回 `analysisWarnings`；warning 只提示后续可拆分，不代表分析失败，也不会删除第 55 集等末尾内容。旧版本把该提示保存为失败任务时，服务会将其识别为可恢复的确定性失败并复用已完成检查点，不重复提交已经保存的分析块。
