# 可选分镜设定板模板

## 目标与使用方式

用户在分镜页选择固定图片模板，把片段的镜头画面、角色妆造参考和审核文字排成横版审核板。首批提供 `classic-nine`（9 张分镜 + 2 组角色三视图）、`eight-one`（8 张分镜 + 1 组角色三视图）、`three-three`（3 张分镜 + 3 组角色三视图）。三视图的一组指同一场景、同一角色的正面/侧面/背面整张参考图。

作品有两种生图模式。旧 `legacy-shot` 作品按九镜兼容，先生成独立镜头图，再排版审核板；新 `segment-board` 作品把一个小说片段作为一次图片生成请求，模型根据剧情选择 3–12 个镜头，并在同一张完整横版整板中表达镜头画面和镜头文字，不上传角色形象图片或生成角色参考区。服务端随后从整板完整画布裁切出每个镜头的 9:16 竖屏原图。整板不是由用户或程序把多张图片手工拼接出来的；视频提交时再上传出场角色参考图。

## 行为规则

- 每种模板有固定画布、固定分镜槽位、固定三视图槽位、固定文字位置；缺少的槽位保留清晰占位，不拉伸重排。
- 具体布局：`classic-nine` 固定 2946×2280，左侧 3×3 镜头卡、右侧两组三视图；`eight-one` 固定 3616×1592，左侧 4×2 镜头卡、右侧一组三视图。两者分镜原图均为 324×576，说明固定在图外右侧。`three-three` 固定 2946×2280，左侧三张 650×2044 大卡片，原图 612×1088、说明固定在图下，右侧三组三视图纵排。所有三视图均保持在右侧并完整 contain 显示。
- 模板控制审核板的排版方向、槽位容量和右侧参考区，不改变片段原有镜头数量、时长、分镜版本、审核状态或视频画幅。切换模板不调用付费模型；`segment-board` 重新生成整板时才会产生图片模型费用。
- 按镜号顺序分页，同一页只包含同一个连续场景的镜头。超过分镜槽位时续页；超过三视图槽位时增加标明“造型续页”的页面，重复该组镜头并展示剩余三视图，不遗漏角色，不混用其他场景服装。分页只影响审核板文件，不改变片段中的镜头数量；`segment-board` 片段可以是 3–12 镜，不要求凑成九镜。
- 单张分镜保持 9:16，所有图像 contain 放入槽位；镜号、时长、运镜、动作、台词均排在固定文字区，超长文字标记截短，完整文字保留于 CSV/manifest。
- 单页文件名 `001.jpg`；多页 `001-01.jpg`、`001-02.jpg` 等。最终视频依然是 `001.mp4`。`gridUrl` 兼容指向第一页，新增 `pages` 提供全部页面及镜号、造型映射。
- 已有作品无模板字段时按 `classic-nine` 读取，无需重新生图。历史导出快照保留；后续预览和导出使用当前模板。

## 接口契约

- `GET /api/board-templates` -> `{ defaultTemplateId, templates: [{ id, name, description, shotCapacity, lookCapacity, shotColumns, shotRows }] }`。
- `PATCH /api/projects/:projectId/segments/:segmentId` 接收且仅接收 `{ boardTemplateId }`，保存片段偏好。未知模板返回 `INVALID_INPUT`，状态 400。该操作不修改任何素材版本或审核；当前正在导出的片段拒绝变更，避免任务快照混淆。
- `POST .../segments/:segmentId/preview` 可选 `{ templateId }` 仅用于本次导出；省略则使用片段偏好。返回增加 `templateId`、`pages: [{ number, gridUrl, shotNumbers, lookIds, continuation, layout }]`。
- 成片导出结果同样携带模板和全部 `pages`；现有审核门禁不变。
- Agent 提供 `list_board_templates`、`set_board_template` 和 `approve_segment_board`；`storyboard_preview` 增加可选 `templateId`。共 26 个工具，保留旧工具兼容调用。

## 实施切片与验证

1. 固定模板目录、媒体分页渲染与 manifest；先测 8 格第九镜续页、3 格三页、角色超容量、场景换装、空槽和非法模板。
2. 片段偏好接口、Agent 调用及版本/审核不变回归；测试存储重载和活动导出保护。
3. 前端模板缩略卡、已选状态、模板保存、分页预览和全部图片下载链接；桌面和 390px 窄屏真实浏览器验证。
4. 用现有真实生成图片导出三套样板，目视固定布局、中文文字和三视图完整性；执行 test、check、build 并审查。

## 边界

本轮不添加自由拖拽模板编辑器。旧 `legacy-shot` 的九镜片段契约继续保留；新 `segment-board` 由分析模型决定 3–12 个真实镜头，模板只决定审核板的容纳量和参考区布局，不负责生成或手工合成图片。用户人工检查整板和全部竖屏裁切画面并通过 `approve_segment_board` 前不得提交视频。
