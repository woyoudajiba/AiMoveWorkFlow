# 映序 · 小说短剧工作台

Windows 本地桌面工具。小说按章节/文本块分析为人物、连续场景和短剧片段。新片段由 AI 按剧情决定镜头数量和时长，一次生成包含画面、镜头文字、当前片段妆造与一致性参考的完整横版分镜板，再由服务端裁切出每个镜头的 9:16 竖屏图。人工审核通过后逐镜头提交 MiniMax 或火山方舟，视频阶段同时上传人物参考图，最终裁切合成为按数字编号的视频；旧作品继续兼容九镜流程。

## 启动

Windows x64 用户下载 `YingXu-2026-10-06-v3-win-x64-setup.exe` 后运行安装程序。安装器不是便携版，会在安装过程中允许选择安装目录，并创建桌面和开始菜单快捷方式；无需安装 Node.js、FFmpeg 或其他依赖。当前安装包未签名，Windows 可能显示来源提示。客户端正式运行时连接云端工作台，安装目录只保存程序文件。客户端侧边栏支持检查更新，点击后会打开更新面板，显示检查状态、版本差异和更新说明；发现新版本后可在面板内下载并启动安装程序。版本号按“日期-当日版次”递增，例如 `2026-10-06-v3`。

启动后使用已有美怡莱 TDL 账号登录，同一套账号密码通过固定 HTTPS 接口验证。网页端和正式客户端按同一个 TDL 账号使用同一套云端作品、媒体、模型配置、任务和历史台账；同一账号可在两个窗口同时使用，退出一端不会踢掉另一端。网页部署在子路径时设置 `AI_FRAME_BASE_PATH`（例如 `/workf`），让媒体和导出链接保留该公开前缀。旧客户端本机目录仍保留，但本次不会静默上传或覆盖云端内容；如需迁移应使用后续的显式迁移流程。云端服务应允许 `AI_FRAME_ALLOWED_HOSTS=wsfile.cn` 和 `AI_FRAME_ALLOWED_ORIGINS=https://wsfile.cn`，否则桌面客户端会被来源校验拒绝。断网无法验证或账号失效时工作台锁定；恢复网络后点击“重新验证”。已接受的后台任务仍属于当前账号。账号注册或密码问题沿用 TDL 处理。

Agent 需先在该本机实例登录，再调用 CLI / MCP；退出或切换账号会使已有 Agent 会话失效。详细接口与边界见 `docs/AGENT.md`，登录设计见 `docs/TDL-AUTH-SPEC.md`。

源码启动需要 Node.js 22.12+（本项目使用 Node 24 验证）。在本目录打开 PowerShell 7：

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

依赖包含 Electron、FFmpeg 和 FFprobe，首次安装依赖会下载运行时。构建后也可双击 `启动映序.cmd`。

生成 Windows x64 安装包：`npm.cmd run dist:win`，结果在 `release/`，安装时可选择目录。需要便携版时使用 `npm.cmd run dist:win:portable`，但网页默认下载入口始终是安装包。`npm.cmd run smoke:electron -- <EXE绝对路径>` 可在独立临时数据目录验证打包运行时，不读取用户项目、不调用付费模型。打包只包含应用与运行依赖，不含小说、生成素材或密钥。

浏览器开发模式：

```powershell
npm.cmd run dev
```

打开 http://127.0.0.1:4317 。开发服务仅监听本机；请不要将开发服务器或数据目录映射公网。

## 参考技能融合（0.2.1）

分析现在保留原文的证据来源、人物认知和伏笔揭示顺序，并携带有界的前文尾段与片段摘要改善长篇接续。人物身份与场景服装分层；三视图补充同高、同地线与严格正侧背要求。图像和视频提示强调动作因果、轴线、视线、道具交接、伤势及湿损连续性。只有相邻同场景、相同出场人物的镜头会携带前镜文字计划；它不是已审核图像，不能保证模型实际满足视觉连续性。

这些优化自动用于桌面、JSON CLI 与 MCP 的同一生成链路，不新增付费步骤、不自动审核；成片保持 9:16，新的片段整板模式由 AI 决定 3–12 个镜头和推荐时长，旧作品继续兼容九镜流程。审核板文字仍由软件排版。提供的小说技能用于写作方法与忠实改编，不代表软件新增了小说创作界面。详见 docs/REFERENCE-SKILLS-REVIEW.md。

## 使用顺序

1. 点击「导入内容」，输入标题、内容类型、画幅和风格。支持小说、剧本、讲解文章、论文、新闻及自动识别；新项目可选择 9:16 竖屏或 16:9 横屏，整板裁切、镜头图片、视频请求和最终成片沿用同一画幅。默认按内容推荐 15/30 秒（同一作品可混合）；也可取消自动推荐，固定片段时长。粘贴正文或选择 UTF-8 TXT/Markdown，最多 120000 字符。超过限制请按章节分成多个作品。可先「体验示例」查看固定虚构内容的文本分镜；示例不会调用模型，也没有伪造的生成图片。
2. 在「模型连接」选择文字模型，填写对应的 Coding Plan 或 Token Plan 密钥，以及所需的 Grsai、MiniMax、熊猫Ai 或火山方舟密钥。小说、相关角色参考和分镜会在点击对应生成操作后发送给所选服务。密钥不会写入项目源码或返回给前端。
3. 分析小说后，复核人物主配角、别名、原文依据与外貌。原文未描写的部分作为创作设定人工确认。可为人物生成/上传基础身份图作为稳定身份参考；新片段不要求先生成独立场景三视图，场景中的服装、配饰和发型由整段分镜板一起生成并供你检查。旧九镜作品仍按原有身份→场景造型流程工作。
4. 新片段由模型按剧情决定 3–12 个镜头和 15/30 秒片段时长。系统只调用一次图片模型生成完整横版分镜板，板内包含所有镜头、编号/文字、当前片段妆造和一致性参考；服务端随后裁切出对应的 9:16 竖屏画面。修改正文、场景或角色会撤销整板和相关视频审核。旧作品仍保留九个独立分镜兼容。
5. 选择审核板模板：经典九镜（9 个版位＋2 组造型）、八镜单角（8 个版位＋1 组造型）、三镜精看（3 个版位＋3 组造型）。模板只决定审核板排版；AI 选择的镜头数量超过单页容量时自动续页，不能借模板把多个图片请求拼成一个片段。检查整板和服务端裁切的竖屏原图后，使用“审核整段分镜板”确认。
6. 审核通过后生成视频。片段级模式每个片段只提交一个完整视频任务；请求按镜头顺序携带去除底部审核文字区的单镜头裁切图，第一张作为片段起始画面，其余裁切图和角色一致性图作为后续参考，整张带编号/说明文字的审核板不会上传。提示词要求按 1 到 N 连续发展，不重新生成分镜板、分屏、字幕或额外人物。旧模式仍逐镜生成视频；失败只重试对应任务，不自动重新付费提交。
7. 在播放器中检查视频。在已验证的素材时长内调整剪辑入点或镜头时长，可以重新审核后复用原视频；超出范围或修改画面内容需要重新生成。导出为 `001.mp4` 等。每次导出是独立目录，保留所有设定板 JPG、台词/分镜 CSV 和 JSON 映射清单；单页为 `001.jpg`，多页为 `001-01.jpg`、`001-02.jpg` 等。未完成、未审核、旧版本或视频时长不足都会阻止导出。

## 模型与凭据

| 能力 | 服务 | 默认模型 | 环境变量（可选） |
| --- | --- | --- | --- |
| 小说与角色分析（Coding Plan） | 阿里云 Coding Plan | qwen3.7-plus | DASHSCOPE_API_KEY（兼容 QWEN_API_KEY / ALIBABA_CODING_PLAN_API_KEY） |
| 小说与角色分析（Token Plan） | 阿里云 Token Plan | 在设置中选择 | TOKEN_PLAN_API_KEY（兼容 ALIBABA_TOKEN_PLAN_API_KEY） |
| 角色与分镜图片 | Grsai 国内节点 | gpt-image-2.5（与智投一致） | GRSAI_API_KEY |
| 分镜视频 | MiniMax / 熊猫Ai / 火山方舟 | MiniMax-H3；熊猫Ai 支持 Seedance 2.0 官方直连与特价按秒的标准、Fast、Mini 变体 | MINIMAX_API_KEY / XIONGMAO_API_KEY（旧别名 `XIONGMAO_MINIMAXH3_API_KEY`）/ ARK_API_KEY；服务端默认模型可用 AIFRAME_VIDEO_MODEL |

文字模型与 WorkHelper 的六个预设一致，默认仍为 `qwen3.7-plus`：

| 模型 | 所属服务 | 推荐 |
| --- | --- | --- |
| Qwen 3.7 Plus | Coding Plan | 默认 |
| Qwen 3.6 Plus | Coding Plan | — |
| Qwen 3.8 Max | Token Plan | — |
| Qwen 3.8 Flash | Token Plan | 快速推荐 |
| DeepSeek V4.1 Flash | Token Plan | 快速推荐 |
| DeepSeek V4 Pro | Token Plan | — |

两类服务使用独立密钥，切换模型后按当前模型判断能否分析。只选择和保存模型不会发起付费请求；同一次长篇分块分析保持提交时的模型，后续选择影响下一次分析。配置标记只表示已录入，不代表账号权限、额度或真实生成效果已经验证。

视频模型也按供应商隔离密钥。MiniMax 使用 `MiniMax-H3` / `MiniMax-H3-Max`；熊猫Ai 使用 `xiongmao-minimaxh3`，以及 `xiongmao-seedance-2-0-official[-fast|-mini]`、`xiongmao-seedance-2-0-promo[-fast|-mini]` 和 `xiongmao-seedance-2-0-special[-fast|-mini]`。按秒 Seedance 变体分别调用熊猫端 `seedance-2-0-official` 或 `seedance-2-0-promo`，基础版传 `quality: 标准`，`-fast` 传 `fast`，`-mini` 传 `mini`；按次变体调用 `seedance-2-0-special`，对应 `高清`、`快速`、`标准`，固定 15 秒。火山方舟使用 `doubao-seedance-*`。MiniMax H3 V2 的 `first_frame` 与 `reference_image` 不能混用：有角色参考图时，已审核分镜图和角色图全部使用 `reference_image`，分镜图排在图片 1；没有角色参考图时才使用单独 `first_frame`。熊猫Ai 使用 `POST /v1/files` 顺序上传本地参考图，再向固定的 `https://panda.token6688.com/v1/videos/generations` 提交顶层参数和 `client_request_id`，完成后通过 `/v1/tasks/{task_id}` 读取 `output_url`。官方直连与特价按秒的目录会显示按截图整理的每秒价格区间，按次目录价格仍显示待确认，任务提交仍以供应商实际账单为准。火山方舟保留已审核分镜图作为首帧并追加人物 `reference_image`。提示词最后固定追加“与参考素材完全一致”。方舟 2.5 支持 4–30 秒，2.0 系列支持 4–15 秒，1.0 Pro / Pro Fast 支持 2–12 秒；熊猫Ai Seedance 2.0 按秒变体支持 4–15 秒。2.5 与 2.0 首帧任务使用 `adaptive` 比例保持首帧画幅，1.0 使用作品比例。模型 ID 需要在方舟账号已开通的模型列表中确认，未开通或余额不足不会自动切换到其他供应商。

接口地址固定在主进程适配器内，不能由小说内容或前端指定。模型选择保存在设置中；服务端也可用 `AIFRAME_VIDEO_MODEL=MiniMax-H3` 或其他已接入模型设置默认值。不会在请求失败后静默切换模型或供应商。图片模型目录已按智投实际源码统一，包含 GPT Image 2.5、GPT Image 2.5 Sunburst、GPT Image 2、GPT Image 2 VIP、Nano Banana Pro，以及映序保留的 Nano Banana Fast / 2。原先预留的 `gpt-image-2.5-vip` 没有智投实现依据，已移除；Sunburst 是独立模型，不是该名称的别名。已有的有效模型选择继续保留。

「模型连接」显示后端提供的同一份模型目录及画幅说明。GPT Image 不传 Nano 的 `imageSize` 字段；VIP 使用像素尺寸，Nano 使用 1K 草稿分辨率。详见 [图片模型配置来源与参数](docs/IMAGE-MODELS.md)。源码核对和本地测试不代表真实账号已完成生图验收。

Windows 桌面版使用 Electron safeStorage（Windows DPAPI）加密凭据文件，绑定当前系统用户。设置中的空密钥表示保留原值。浏览器开发版仅在服务端进程内保存密钥，重启后需重填或通过环境变量配置；`.env.example` 仅说明变量，应用不会自动加载 `.env`。

## Agent 调用

提供共用本地工作台 API 的 JSON 命令行和标准 stdio MCP，共 26 个工具，覆盖小说分析、人物身份、场景造型与三视图、片段整板分镜、显式版本审核、模板目录/选择、任务查询/恢复及导出。先在本目录运行 `npm.cmd run server`，默认仅监听 `http://127.0.0.1:4318`；模型凭据沿用服务进程环境变量。

```powershell
node scripts/agent-cli.mjs list
node scripts/agent-cli.mjs call studio_status
node scripts/agent-mcp.mjs --url http://127.0.0.1:4318
```

生图工具默认复用当前版本素材，重做必须传 `regenerate:true`；审核必须声明 `reviewedVersion`，不会自动批准视频。`list_board_templates` 列出模板，`set_board_template` 保存片段偏好；`storyboard_preview` 可在视频生成前导出全部设定板 JPG、CSV 和 JSON，也可传 `templateId` 临时预览另一模板。参数、调用顺序及无密钥 MCP 配置示例见 [Agent 调用说明](docs/AGENT.md)。原创实测小说见 [末班灯](examples/末班灯.md)。

已用《末班灯》完成真实 Qwen 分析、GPT Image 2.5 角色定妆与九镜图片生成，以及 CLI/MCP 调用验收。结果在 `output/real-test/001.jpg`、`output/real-test/shots/001.png` 至 `009.png` 和 `output/real-test/report.md`；图片仍待用户审核，未提交视频任务。详细验证与边界见 [验证记录](docs/VALIDATION.md)。

## 数据与恢复

正式桌面客户端的作品、媒体、任务和历史保存在云端账号工作区；安装目录只保存程序文件。浏览器开发版和显式本地模式仍可使用本项目 `data/` 与 `AI_FRAME_DATA_DIR`，旧本地项目不会自动上传。网页端不写用户电脑，只在服务器保留媒体并提供下载链接；客户端的下载操作由 Windows 下载器保存到用户选择的位置。服务器端仍保留所有 `/media` 文件与项目 JSON。备份云端数据时应备份完整服务器 `data` 目录；本地开发或旧客户端数据另行备份。

视频 POST 之前先原子保存业务 ID，成功后保存供应商任务 ID。关闭或超时后只查询已有任务，不重发已提交请求。结果不明确显示「待核实」，应恢复查询；图片已生成但下载失败会保存私有回执，恢复操作仅重试下载。图片提交本身无法确认时，需供应商核实，不能直接盲目重试。已明确失败的任务可以重新点击生成。同一数据目录有系统进程锁，防止多个程序同时恢复任务。

旧作品升级为场景造型流程时，原图、视频和文字仍保留，但旧肖像不会自动当作三视图，旧分镜须根据当前造型重新生成或上传并审核。原导出记录保留在 `legacyExports`，不会作为新造型的有效交付。已经采用场景造型流程的作品只缺模板字段时，按 `classic-nine` 读取，不改变审核或素材版本；切换模板保留历史导出，后续预览/导出使用当前模板。历史横屏作品继续兼容。

## 当前边界

- 旧九镜流程中 15 秒平均 1.67 秒，30 秒更适合剧情；新的片段整板流程按分析模型决定 3–12 个镜头和镜头时长，实际输出仍受所选视频模型的时长限制。
- 首版输出静音视频，台词保存在 CSV。尚未接入统一配音、音乐或自动字幕烧录，避免直接裁切模型人声导致对白中断。
- 当前使用统一作品风格、人物身份参考和每个连续场景的独立三视图造型；支持同一人物跨场景换装，尚无自由拖拽模板编辑器、自动合并整季或项目打包导入导出。
- 参考图能约束角色形象，不能保证绝对一致。文本文学质量、角色相似度、台词适配及真实视频输出仍需人工验收。
- Qwen 与图片模型已有受控实图验证，具体结果见验证记录；人工审核前不提交视频。MiniMax 与火山方舟的真实视频账号、计费、模型 ID、参考图遵循和接口版本仍需真实接入验收。
