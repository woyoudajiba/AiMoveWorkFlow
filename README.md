# 映序 · 小说短剧工作台

映序是一个从原始文字到可审核视频片段的 Windows 工作台。它会把小说、剧本、论文、新闻或讲解文章按内容逻辑分析为人物、场景、关键物品、对白/旁白和镜头计划，再生成可审核的分镜素材，最后提交一条完整片段视频并按编号导出项目成片。

当前源码版本为 `2026.10.9-v16`，客户端显示版本为 `2026-10-09-v16`。新项目默认使用片段整板（`segment-board`）流程；旧项目仍兼容九镜（`legacy-shot`）流程。

## 启动

Windows x64 用户下载 `YingXu-2026-10-09-v16-win-x64-setup.exe` 后运行安装程序。构建目录中的原始安装包名称为 `YingXu-2026.10.9-v16-win-x64-setup.exe`；发布到更新地址后，脚本会按 `clientVersion` 生成日期版次文件名。安装器允许选择安装目录，并创建桌面和开始菜单快捷方式；无需安装 Node.js、FFmpeg 或其他依赖。当前安装包未签名，Windows 可能显示来源提示。客户端正式运行时连接云端工作台，安装目录只保存程序文件，并在应用目录旁自动维护 `output/` 本地导出副本。客户端侧边栏的“检查更新”会打开更新面板，显示检查状态、版本差异、校验值和更新说明，确认后下载并启动安装程序。版本号按“日期-当日版次”递增，例如 `2026-10-09-v16`。

启动后使用已有美怡莱 TDL 账号登录，同一套账号密码通过固定 HTTPS 接口验证。网页端和正式客户端按同一个 TDL 账号使用同一套云端作品、媒体、模型配置、任务和历史台账；同一账号可在两个窗口同时使用，退出一端不会踢掉另一端；不同账号同时在线时也各自保持独立会话。网页部署在子路径时设置 `AI_FRAME_BASE_PATH`（例如 `/workf`），让媒体和导出链接保留该公开前缀。云端服务应允许 `AI_FRAME_ALLOWED_HOSTS=wsfile.cn` 和 `AI_FRAME_ALLOWED_ORIGINS=https://wsfile.cn`，否则桌面客户端会被来源校验拒绝。断网无法验证或账号失效时工作台锁定；恢复网络后点击“重新验证”。已接受的后台任务仍属于当前账号。账号注册或密码问题沿用 TDL 处理。

Agent 需先在该本机实例登录，再调用 CLI / MCP；退出或切换账号会使已有 Agent 会话失效。详细接口与边界见 `docs/AGENT.md`，登录设计见 `docs/TDL-AUTH-SPEC.md`。

源码启动需要 Node.js 22.12+（本项目使用 Node 24 验证）。在本目录打开 PowerShell 7：

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

依赖包含 Electron、FFmpeg 和 FFprobe，首次安装依赖会下载运行时。构建后也可双击 `启动映序.cmd`。

生成 Windows x64 安装包：`npm.cmd run dist:win`，结果在 `release/`，安装时可选择目录。需要便携版时使用 `npm.cmd run dist:win:portable`，但网页默认下载入口始终是安装包。`npm.cmd run smoke:electron -- <EXE绝对路径>` 可在独立临时数据目录验证打包运行时，不读取用户项目、不调用付费模型。打包只包含应用与运行依赖，不含小说、生成素材或密钥。

浏览器开发模式：

```powershell
npm.cmd run dev
```

打开 http://127.0.0.1:4317 。开发服务仅监听本机；请不要将开发服务器或数据目录映射公网。

## 参考技能融合（0.2.1）

分析现在保留原文的证据来源、人物认知和伏笔揭示顺序，并携带有界的前文尾段与片段摘要改善长篇接续。人物身份与场景服装分层；三视图补充同高、同地线与严格正侧背要求。图像和视频提示强调动作因果、轴线、视线、道具交接、伤势及湿损连续性。只有相邻同场景、相同出场人物的镜头会携带前镜文字计划；它不是已审核图像，不能保证模型实际满足视觉连续性。

这些优化自动用于桌面、JSON CLI 与 MCP 的同一生成链路，不新增付费步骤、不自动审核；成片保持项目选择的 9:16 或 16:9 画幅，新的片段整板模式由 AI 决定 3–12 个镜头和推荐时长，旧作品继续兼容九镜流程。审核板文字仍由软件排版。提供的小说技能用于写作方法与忠实改编，不代表软件新增了小说创作界面。详见 docs/REFERENCE-SKILLS-REVIEW.md。

## 使用顺序

1. 点击「导入内容」，输入标题、内容类型、画幅、视觉媒介和叙事视角。支持小说、剧本、讲解文章、论文、新闻及自动识别；新项目可选择 9:16 竖屏或 16:9 横屏，并可选择仿真人、2D 动画或 3D 动画。旁白视角适合广告、纪录片、新闻和论文，主角视角用于主观观察，自动分析由模型判断；原文明确对白始终保留。新项目分析出的普通片段均不超过 15 秒，由 AI 按对白、动作、节奏和画面信息密度分配每镜时长。粘贴正文或选择 UTF-8 TXT/Markdown，最多 300000 字符。可先「体验示例」查看固定虚构内容的文本分镜；示例不会调用模型，也没有伪造的生成图片。
2. 在「模型连接」选择项目使用的文字模型，填写对应的 Coding Plan 或 Token Plan 密钥，以及所需的 Grsai、MiniMax、熊猫Ai 或火山方舟密钥。模型设置按账号保存；同一账号可以让不同项目使用不同文字模型，并可并发分析。密钥不会写入项目源码或返回给前端。
3. 分析内容后，复核人物主配角、别名、原文依据、场景、服装和关键物品。分析按块保存检查点，前面块完成后即可继续生成可用素材；失败、暂停或网络中断可从最近检查点继续，不会重复提交已保存块。原文未描写的部分作为创作设定人工确认，分析不会因为可修复的逻辑问题直接卡死。剧集标题会作为集数边界，剧集通常规划约 80–120 秒，突破、Boss 战和关键打斗等重要剧情可超出范围；后续可在原始内容下方追加续集并增量分析。
4. 新片段由模型按剧情决定 3–12 个镜头和不超过 15 秒的片段时长。系统只调用一次图片模型生成完整横版分镜板，板内同时表达画面、镜头编号、当前片段妆造、关键物品和一致性参考；服务端再裁切出对应画幅的无审核文字镜头图。镜头编号只是顺序，不等于秒数；对白、动作、停顿、运镜、打斗和突破会独立决定每镜时长。需要更长连续表演时，用户可在片段页把同一连续场景明确扩展到 30 秒，系统会重排镜头并要求重新生成、审核；只有支持 30 秒的模型可提交。
5. 分析完成后选择模式：九宫格模式（`segment-board`）先审核整段分镜板，再生成一条完整片段视频；传统模式（`traditional`）跳过九宫格，直接把当前片段实际使用的场景图、人物身份/造型图和关键物品图作为多参考图，生成同一条完整片段视频。两种模式都不会把一个镜头拆成一条视频任务。
6. 审核页的经典九镜、八镜单角、三镜精看模板只决定固定排版，不决定 AI 镜头数量，也不会把多个图片请求拼成一段。模板容量不足时自动续页。确认整板或传统模式素材后，生成视频请求只携带无编号、无格线、无中文说明的镜头裁切图和必要参考图；审核板文字不会上传给视频模型。提示词要求按镜头编号顺序连续发展，不重新生成分镜板、分屏、字幕或额外人物。
7. 在播放器中检查视频并进入历史台账。片段模式每个片段只保存一条完整视频；项目导出会按片段编号合并成一条总成片，同时保留每段视频、设定板 JPG、中文提示词、台词/分镜 CSV 和 JSON 映射清单。客户端可为项目选择本地文件夹，自动维护 `Analysis`、`Actor_image`、`Story_image`、`Movie` 四个固定目录；同步成功后可确认清理服务器视频，网页端继续从历史页查看仍保留的图片、分析和导出记录。

## 模型与凭据

普通分析片段默认不超过 15 秒。熊猫 `xiongmao-seedance-2-5-special` 是固定 30 秒按次模型，只有在片段页明确扩展同一连续场景到 30 秒并重新生成、审核素材后才可选择；其他模型按其目录中的时长上限校验。

| 能力 | 服务 | 默认模型 | 环境变量（可选） |
| --- | --- | --- | --- |
| 小说与角色分析（Coding Plan） | 阿里云 Coding Plan | qwen3.7-plus | DASHSCOPE_API_KEY（兼容 QWEN_API_KEY / ALIBABA_CODING_PLAN_API_KEY） |
| 小说与角色分析（Token Plan） | 阿里云 Token Plan | 在设置中选择 | TOKEN_PLAN_API_KEY（兼容 ALIBABA_TOKEN_PLAN_API_KEY） |
| 角色与分镜图片 | Grsai 国内节点 | gpt-image-2.5（与智投一致） | GRSAI_API_KEY |
| 分镜视频 | MiniMax / 熊猫Ai / 火山方舟 | MiniMax-H3 / H3 Max；熊猫Ai Seedance 2.0 变体和 Seedance 2.5 特价按次模型；火山方舟 Seedance 2.0 / 2.5 | MINIMAX_API_KEY / XIONGMAO_API_KEY（旧别名 `XIONGMAO_MINIMAXH3_API_KEY`）/ ARK_API_KEY；服务端默认模型可用 AIFRAME_VIDEO_MODEL |

文字模型与 WorkHelper 的六个预设一致，默认仍为 `qwen3.7-plus`：

| 模型 | 所属服务 | 推荐 |
| --- | --- | --- |
| Qwen 3.7 Plus | Coding Plan | 默认 |
| Qwen 3.6 Plus | Coding Plan | — |
| Qwen 3.8 Max | Token Plan | — |
| Qwen 3.8 Flash | Token Plan | 快速推荐 |
| DeepSeek V4.1 Flash | Token Plan | 快速推荐 |
| DeepSeek V4 Pro | Token Plan | — |

两类服务使用独立密钥，切换模型后按当前模型判断能否分析。只选择和保存模型不会发起付费请求；同一次长篇分块分析保持提交时的模型，后续选择影响下一次分析。配置标记只表示已录入，不代表账号权限、额度或真实生成效果已经验证。

视频模型也按供应商隔离密钥。目录包含 `MiniMax-H3`、`MiniMax-H3-Max`、熊猫 Ai 的 `xiongmao-minimaxh3`、Seedance 2.0 官方直连/特价按秒/特价按次三组标准、Fast、Mini 变体、`xiongmao-seedance-2-5-special`，以及火山方舟的 `doubao-seedance-2-5`、`doubao-seedance-2-0-pro`、`doubao-seedance-2-0-fast`、`doubao-seedance-2-0-mini`；Seedance 1 已不在目录中。熊猫 2.5 特价模型固定 30 秒，支持 720p/1080p，价格由供应商返回，界面显示待确认。MiniMax H3 V2 的 `first_frame` 与 `reference_image` 不能混用：有角色参考图时，已审核分镜图和角色图全部使用 `reference_image`，分镜图排在图片 1；没有角色参考图时才使用单独 `first_frame`。熊猫 Ai 先通过 `POST /v1/files` 顺序上传本地参考图，再向固定视频接口提交顶层参数和 `client_request_id`，完成后轮询任务并下载结果。火山方舟保留已审核分镜图作为首帧并追加人物 `reference_image`。服务端不会在失败后静默切换供应商或模型，模型 ID 和账号开通状态需要由实际供应商确认。

接口地址固定在主进程适配器内，不能由小说内容或前端指定。模型选择保存在设置中；服务端也可用 `AIFRAME_VIDEO_MODEL=MiniMax-H3` 或其他已接入模型设置默认值。不会在请求失败后静默切换模型或供应商。图片模型目录已按智投实际源码统一，包含 GPT Image 2.5、GPT Image 2.5 Sunburst、GPT Image 2、GPT Image 2 VIP、Nano Banana Pro，以及映序保留的 Nano Banana Fast / 2。原先预留的 `gpt-image-2.5-vip` 没有智投实现依据，已移除；Sunburst 是独立模型，不是该名称的别名。已有的有效模型选择继续保留。

「模型连接」显示后端提供的同一份模型目录及画幅说明。GPT Image 不传 Nano 的 `imageSize` 字段；VIP 使用像素尺寸，Nano 使用 1K 草稿分辨率。详见 [图片模型配置来源与参数](docs/IMAGE-MODELS.md)。源码核对和本地测试不代表真实账号已完成生图验收。

Windows 桌面版使用 Electron safeStorage（Windows DPAPI）加密凭据文件，绑定当前系统用户。设置中的空密钥表示保留原值。浏览器开发版仅在服务端进程内保存密钥，重启后需重填或通过环境变量配置；`.env.example` 仅说明变量，应用不会自动加载 `.env`。

## 提示词与对白规则

提示词把台词、旁白和画面规划分开处理。原文明确的角色对白按逐句角色绑定，不能因为人物位置、参考图顺序或镜头显著性而换人；`dialogue` 为空时不生成可辨识的人声或说话口型。原文明确的群众吆喝、叫卖、欢呼和口号可以作为远处环境声，其余群众只做无声背景动作。旁白只来自当前镜头的 `narration` 字段。分镜板、参考图、三视图、OCR 文字、编号、标签、提示词和占位语句都属于视觉元数据，不能被视频模型朗读、转写或变成对白。输出视频禁止出现九宫格编号、中文说明、格线、字幕、对白框、水印或“原文未描述/待确认”等内部文本；字幕由用户后期添加。

## Agent 调用

提供共用本地工作台 API 的 JSON 命令行和标准 stdio MCP，共 28 个工具，覆盖项目创建与续集增量分析、人物身份、场景造型与三视图、关键物品、片段整板分镜、传统模式视频、显式版本审核、模板目录/选择、任务查询/暂停/恢复及导出。Agent 与网页和 Electron 使用同一业务服务、同一账号工作区和同一套提示词，不接收密钥或任意外部 URL。先在本目录运行 `npm.cmd run server`，默认仅监听 `http://127.0.0.1:4318`；模型凭据沿用服务进程环境变量。

```powershell
node scripts/agent-cli.mjs list
node scripts/agent-cli.mjs call studio_status
node scripts/agent-mcp.mjs --url http://127.0.0.1:4318
```

生图工具默认复用当前版本素材，重做必须传 `regenerate:true`；审核必须声明 `reviewedVersion`，不会自动批准视频。`list_board_templates` 列出模板，`set_board_template` 保存片段偏好；`storyboard_preview` 可在视频生成前导出全部设定板 JPG、CSV 和 JSON，也可传 `templateId` 临时预览另一模板。任务状态不明确时只能调用恢复/查询，不会自动重发付费请求。参数、调用顺序及无密钥 MCP 配置示例见 [Agent 调用说明](docs/AGENT.md)。原创实测小说见 [末班灯](examples/末班灯.md)。

已用《末班灯》完成真实 Qwen 分析、GPT Image 2.5 角色定妆与九镜图片生成，以及 CLI/MCP 调用验收。结果在 `output/real-test/001.jpg`、`output/real-test/shots/001.png` 至 `009.png` 和 `output/real-test/report.md`；图片仍待用户审核，未提交视频任务。详细验证与边界见 [验证记录](docs/VALIDATION.md)。

## 数据、历史与恢复

正式桌面客户端的作品、媒体、任务和历史保存在云端账号工作区，同时把完成的导出复制到客户端 `output/`。浏览器端不写用户电脑，只在服务器保留媒体并提供下载链接；客户端可按项目选择本地根目录，固定创建 `Analysis`、`Actor_image`、`Story_image`、`Movie`，分析快照、原始内容、角色/造型图、分镜图、视频和清单按目录保存。同步必须先完成本地写入，用户确认后才可清理已下载的视频；服务器图片、分析数据和历史台账仍保留。服务器端仍保留 `/media` 文件与项目 JSON，备份云端数据时应备份完整服务器 `data` 目录。

视频 POST 之前先原子保存业务 ID，成功后保存供应商任务 ID。关闭或超时后只查询已有任务，不重发已提交请求。结果不明确显示「待核实」，应恢复查询；图片已生成但下载失败会保存私有回执，恢复操作仅重试下载。图片提交本身无法确认时，需供应商核实，不能直接盲目重试。已明确失败的任务可以重新点击生成。同一数据目录有系统进程锁，防止多个程序同时恢复任务。

旧作品升级为场景造型流程时，原图、视频和文字仍保留，但旧肖像不会自动当作三视图，旧分镜须根据当前造型重新生成或上传并审核。原导出记录保留在 `legacyExports`，不会作为新造型的有效交付。已经采用场景造型流程的作品只缺模板字段时，按 `classic-nine` 读取，不改变审核或素材版本；切换模板保留历史导出，后续预览/导出使用当前模板。历史横屏作品继续兼容。

## 当前边界

- 旧九镜流程中 15 秒平均 1.67 秒，30 秒更适合剧情；新的片段整板流程按分析模型决定 3–12 个镜头和镜头时长，实际输出仍受所选视频模型的时长限制。
- 视频供应商是否返回音轨由模型接口决定；映序不会从分镜板文字生成额外台词、旁白或字幕，也不会自动烧录字幕。对白、旁白和环境声规则通过视频提示词约束，真实音频效果仍需按供应商验收。
- 当前使用统一作品风格、人物身份参考和每个连续场景的独立造型；支持同一人物跨场景换装、关键物品和群众环境层。审核模板是固定排版，不能自由拖拽编辑；项目成片按当前已生成片段合并，不自动替用户创作缺失剧情。
- 参考图能约束角色形象，不能保证绝对一致。文本文学质量、角色相似度、台词适配及真实视频输出仍需人工验收。
